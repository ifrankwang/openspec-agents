> **项目规范优先**：本 skill 所列约定为推荐标准。若项目已有明确规范且与本 skill 不一致，以项目规范为准。

## 路径约定

| # | 规则 | 说明 |
|---|------|------|
| 1 | 路径统一 `{context-path}/api/v1/` 前缀 + kebab-case | 如 `{context-path}/api/v1/orders/{orderId}/items` |
| 2 | RESTful 风格 | 禁止 POST 包打天下；GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除 |

## 接口层职责

接口层（Controller / Handler）职责边界：

| 职责 | 说明 |
|------|------|
| 参数校验 | 校验入参合法性（必填、格式、长度、枚举值），校验失败返回 4xx |
| 调用下层 | 校验通过后调用应用层服务编排业务 |
| 响应转换 | 将业务结果转换为响应格式（DTO） |
| **禁止** | 不写业务逻辑、不直接访问持久化层 |

## 统一响应结构

所有接口统一返回结构，含以下三部分：

- `code`：业务错误码（数字），成功时为约定成功值
- `message`：错误描述，支持动态占位参数
- `data`：业务数据泛型

文件下载等特殊场景可例外。

## 异常响应体系

接口层不直接处理异常，由全局异常处理器统一拦截。HTTP 状态码与异常语义映射：

| 异常语义 | HTTP 状态码 | 含义 |
|---------|------------|------|
| 资源不存在 | 404 | 请求的资源未找到 |
| 状态冲突 | 409 | 如重复提交、状态不允许 |
| 文件类型不合法 | 415 | 不支持的媒体类型 |
| 参数校验失败 | 400 | 输入不合法 |
| 服务端业务异常 | 500 | 业务处理错误 |
| 外部服务异常 | 500 | 依赖的外部服务调用失败 |
| 其他未捕获异常 | 500 | 兜底 |

业务错误码作为响应体中独立数字字段，与 HTTP 状态码解耦。HTTP 码供客户端/网关判断大类，业务错误码供前端精确分支处理。

## 版本演进与废弃

- 版本号在路径上体现（如 `/api/v1/`）；路径版本变更需说明并存期与迁移窗口：新版本上线后旧版本保留多久、窗口内两边行为差异如何保持一致
- 破坏性变更必须提供迁移说明与调用方适配期：字段删除或重命名、类型收窄、必填变严、语义变更都属于破坏性；只改实现不改契约不算
- 废弃接口需标注废弃时间与下线时间（注解、契约文档、响应头等可被发现的位置），下线前确认无调用，以网关或访问日志的调用量归零为判据
- 同一业务语义不得长期并存两个版本入口而不给收敛计划：并存须写明保留原因与收敛时间点，长期双轨按技术债口径处理
- 版本内的小改动保持向后兼容：新增字段可选、新增枚举值调用方须能忽略未知值、错误码只增不改语义
- 灰度与回退口径需与发布流程一致：按流量或按调用方灰度切换版本；回退到旧版本时旧接口仍可用
- 契约文档（OpenAPI 等）随版本同步更新，废弃标记写进契约；契约与实现不一致即为不满足

## 时间与时区

- 接口传输统一用 ISO 8601 带偏移格式（如 `2026-01-05T09:30:00+08:00`），或统一用 UTC 并在契约中显式声明；二选一并全接口一致
- 禁止用无偏移的时间字符串传输（`2026-01-05 09:30:00`、`2026-01-05T09:30:00`），接收方无法判断时区
- 跨时区业务需分别声明存储时区（数据库存 UTC 或统一业务时区）与展示时区（按用户或业务所在地），两者不得混用
- 只有日期含义的字段（生日、账单日、有效期截止日）用纯日期 `YYYY-MM-DD`，不得伪造为带时间的字符串再按本地时区解析
- 时间字段命名体现语义与时区：`createdAt`（带时区的时间点）与 `businessDate`（纯日期）区分，禁止同名承载两种语义
- 服务端不做隐式时区转换：入参按声明的时区解析，出参按声明格式输出；依赖运行环境默认时区即为不满足

## 泛化设计原则（非强约束）

以下为推荐模式，不强制：

| 原则 | 说明 |
|------|------|
| 输入校验 | 入参 String 字段限制长度和特殊字符（InfoSec 合规） |
| 文件上传 MIME | 上传接口接口层校验 MIME/Content-Type，允许类型由项目配置决定 |
