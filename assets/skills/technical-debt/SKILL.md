> **项目规范优先**：本 skill 所列约定为推荐标准。若项目已有明确规范且与本 skill 不一致，以项目规范为准。
> 本文列出**架构维度技术债识别的最低基线**，不限于所列维度。AI 审查时必须结合自身架构知识做拓展覆盖。

## 定位

本 skill 是架构维度的技术债识别框架——识别债务、评估利息（代价）、给出处置分级。只覆盖架构维度可归口的债务类型，不替代各维度规范：识别出的问题按各维度规范归口，同一问题不在多个维度重复报。

### 归口边界

| 债务信号 | 归口 |
|---------|------|
| 测试债（缺测试、断言放水、覆盖空洞） | 测试与行为验证职责 |
| 代码级重复、死代码、魔法数、结构债（方法长度、类职责）、未使用的依赖 | maintainability 维度 |
| 性能债（N+1、缓存缺失、异步滥用） | performance 维度 |
| 安全债（含 EOL 组件的已知安全漏洞） | security 维度 |
| 本次变更引入且未生效的 stub/降级（仅打状态标记未实际生效） | 行为真实性验证职责 |
| 长期滞留的存量临时方案（已生效但为临时代替/降级形态） | 本 skill（临时方案固化） |

## 债务类型

### 过时技术选型

采用已 EOL（End of Life）或被官方弃用的框架、中间件、核心库，或选型决策遗留导致升级成本随时间递增。

- 识别信号：框架/中间件/核心库版本已停止官方支持；官方宣布弃用并给出替代路线；新代码继续基于将被替换的技术栈编写
- 判据：官方支持周期已结束或明确宣布弃用，项目仍长期停留在旧版本且无升级计划
- 利息：安全漏洞无官方修复、新特性缺失、升级成本随时间递增
- 处置：采用 EOL/弃用技术选型且无升级计划 → 至少 Medium 级别 issue

### 技术迁移债

技术栈级新旧并存与迁移中断残留——跨大版本迁移中途停止、新旧技术栈并行运行、迁移只完成部分模块。

- 识别信号：同一技术栈两种大版本并存；迁移后的模块与迁移前模块并行运行；迁移中断留下的过渡状态
- 判据：存在明确的目标技术栈（迁移方向），但存量仍以旧技术栈运行且无完成计划
- 利息：双轨维护成本、行为不一致风险、迁移中断越久重启成本越高
- 处置：迁移中断且无完成计划 → 至少 Medium 级别 issue

### 平行实现与迁移缺失

同类能力多套方案并存且无迁移方案——引入与既有实现功能重叠的新实现且不改动原实现，同类能力多套方案并存。

本类债务从识别与分级视角描述；方案层面引入新实现时的复用与迁移要求属方案规范约束，识别与要求分工互补，不在本 skill 重复。

- 识别信号：同类能力存在 ≥2 套实现；新引入实现与既有实现功能重叠；新旧并存无迁移方案
- 判据：同类能力已有既有实现仍另建实现；并存状态无迁移方案
- 利息：维护与认知成本翻倍、修复不同步、新增场景遗漏调用
- 处置：平行引入且无迁移方案 → 至少 Medium 级别 issue

### 临时方案固化

架构级临时方案长期滞留——绕过分层直连、应急 hack、stub 降级形态进入生产且无跟进。

- 识别信号：绕开架构约束的直连/hack；临时 stub 或降级形态已进入生产；带临时标记但长期未跟进
- 判据：明确标记为临时但滞留超过合理周期；或长期以临时形态运行且无替代计划
- 利息：行为偏差风险、架构一致性破坏、后续变更在此之上叠加
- 处置：临时方案长期固化 → 至少 Medium 级别 issue

### 契约不一致与模型漂移

同一业务语义的数据字段在不同接口/模块间类型或表达不一致——如某接口以枚举表达状态，另一接口以数字码表达同一状态，调用方需维护两套认知与转换。

单点字段类型选型不当（单一接口内字段类型/表达的选择问题）属命名与通用语言约定范畴；跨接口/模块表达不一致才归本类债务。

- 识别信号：同一语义字段在不同接口/模块的 DTO 中类型不一致；同一状态/类型概念有多种表达形态（枚举/数字码/字符串）；跨接口取值需额外转换逻辑
- 判据：同一业务语义存在 ≥2 种表达形态且无统一计划
- 利息：调用方认知与转换成本、语义漂移风险（数字码与枚举映射歧义）、新增接口易沿用错误形态
- 处置：契约不一致且无统一计划 → 至少 Medium 级别 issue

## 存量债务处置

存量（非本轮引入）技术债与新增债务同等识别，不得因非本轮引入而沉默丢弃。存量可识别债务 → 至少 Low+ 级别 issue；纯建议性优化 → Info。
