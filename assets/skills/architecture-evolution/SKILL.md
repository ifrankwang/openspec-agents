> 本文列出**架构维度架构演进审查的最低基线**，不限于所列维度。AI 审查时必须结合自身架构知识做拓展覆盖。

## 定位

本 skill 是架构维度的前瞻性审查框架——评估方案/变更与项目整体架构脉络的契合度与演进合理性。只覆盖架构维度可归口的演进类问题，不替代各维度规范：识别出的问题按各维度规范归口，同一问题不在多个维度重复报。

### 归口边界

| 演进类信号 | 归口 |
|-----------|------|
| 已存在的债务识别与处置分级（过时选型/迁移中断残留/平行实现/临时方案固化/契约不一致） | 技术债识别职责 |
| 代码级重复、死代码、结构债 | 可维护性维度 |
| 术语/命名与通用语言漂移 | 命名与通用语言约定 |
| 分层规则合规、依赖方向违规（绕过分层直连） | 架构分层约定 |
| 方案设计时未复用既有能力/平行引入新实现 | 方案复用与平行实现约定 |
| 本 skill 五类检查与上述职责的相邻边界见各类检查中的划界说明 | 本 skill |

## 检查类别

### 1. 整体架构契合

方案/变更是否延续项目整体架构方向——分层风格、模块边界、架构风格延续、与既有模块的边界关系。

- 识别信号：新模块/新实现与项目既有架构风格相悖；割裂既有模块边界；架构方向上与项目既有路线冲突
- 判据：方案/变更与项目整体架构脉络明显冲突且无说明理由
- 处置：方案/变更与项目整体架构方向冲突且无理由 → 至少 Medium 级别 issue
- 划界：分层规则合规（是否违反分层依赖方向）归架构分层约定；本类关注方向性冲突（风格/边界/路线）

### 2. 长期迭代逻辑

设计是否支持后续迭代演进——新场景/新类型/新渠道扩展时是否需要返工、是否堵死演进路径、是否与项目迭代方向一致。

- 识别信号：扩展新场景需改动核心链路多处；设计固化单一场景假设；演进路径被结构性堵死
- 判据：可预见的后续迭代在现有设计下需结构性返工且方案未考虑
- 处置：可预见的后续迭代需结构性返工且方案未考虑 → 至少 Medium 级别 issue

### 3. 拓展性与兼容性

变更是否破坏既有契约——接口签名、数据格式、行为语义；破坏时是否有兼容或过渡安排；应预留拓展点而未预留。

- 识别信号：修改既有接口签名/响应结构/字段语义且调用方未同步；存量数据/历史行为不兼容；破坏性变更无过渡方案
- 判据：破坏既有契约且无兼容/过渡安排
- 处置：破坏既有契约且无兼容/过渡安排 → 至少 Medium 级别 issue
- 划界：跨接口/模块同一语义表达不一致（枚举 vs 数字码）归契约不一致职责；本类关注变更对既有契约的破坏与兼容安排

### 4. 重构贴合历史逻辑

重构是否保持既有行为语义与历史调用方契约——行为变化是否显式声明、是否无意改变既有语义。

- 识别信号：重构改动既有行为逻辑/边界条件/错误处理语义；重构后行为与重构前不一致且未声明；借重构之名改变契约
- 判据：重构改变既有行为语义且未显式声明
- 处置：重构改变既有行为语义且未显式声明 → 至少 Medium 级别 issue
- 划界：重构场景下破坏契约归本类；非重构场景的新契约破坏归第 3 类。平行引入新实现（另起一套）归方案复用与平行实现约定

### 5. 数据模型搬迁与数据承接

涉及字段/实体承载位置搬迁时，须明确数据承接与迁移设计：新承载位置、产出字段写入目标、存量数据迁移、旧位置兼容与清理；缺失或遗漏产出字段承载点按契约破坏/重构贴合判例处理。
