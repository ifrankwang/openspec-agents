# 业务报告规范

报告是脚本产物，不是分析文档。所有文字来自测试代码里的声明（用例标题、步骤句子、断言源码）和运行时原始数据（控制台、接口、堆栈），不允许出现 AI 生成的结论。

## 一、页面结构

### 列表页

- 顶部工具栏：搜索框、筛选项（全部 / 通过 / 失败 / 跳过，带数量与状态图标）、右侧生成时间与总耗时。
- 分组是三层缩进的树：
  - 一级：业务域（分组卡片头，可折叠）
  - 二级：业务分支（缩进的小标题，可折叠）
  - 三级：场景行（状态图标 + 场景标题 + `文件:行` + 耗时），点击进入详情
- 不用浏览器名、测试类名、spec 文件名做分组维度。

### 详情页

- 顶部：`← 返回场景列表`、面包屑（业务域 / 业务分支）、大标题、`文件:行` + 耗时、状态页签。
- 「操作步骤」卡片：每步编号 + 一句话 + 截图（可点开原图）。
- 失败场景额外有两件事：
  1. 出错那一步的编号和文字标红；
  2. 该步骤截图优先用失败瞬间的截图，并按 `mark` 百分比坐标叠红框 + 「问题位置」标签（红框只由页面叠一层，不要把它烤进截图，否则出现双框）。
- 失败步骤下方渲染证据块：标题行是「分类标签 + 一行机械摘要」，下面按 label/内容两列分块。

## 二、状态

只有三种：`passed`（通过）/ `failed`（失败）/ `skipped`（跳过）。

- `test.fail()` 的期望失败计为 `failed`，并在详情里给完整证据。
- 没有「已知问题」「flaky」「重试」等分类维度。

## 三、失败证据

### 分类与判定（按顺序取第一个命中的）

| 分类 | 标签颜色 | 判定 |
|---|---|---|
| 控制台报错 | 橙 | 用例期间捕获到未捕获异常（pageerror），或错误不是断言类且控制台有 error |
| 接口报错 | 红 | 错误消息里带 `HTTP 4xx/5xx`，或接口直调抛错 |
| 断言不符 | 蓝 | 错误是 expect 断言失败 |
| 脚本异常 | 灰 | 其余错误 |

### 每类展示什么

- **接口报错**：`请求` 块（请求行 + 请求头 + 请求体）、`返回` 块（状态行 + 响应头 + 响应体）、`位置` 块（`文件:行:列`）。
  - 证据来源：fixture 注入的页面内追踪（fetch / XHR 层）回传，mock 与 real 模式同一口径。MSW 在浏览器内（Service Worker）拦截的请求不出现在 Playwright 网络事件里，因此不依赖网络事件采集；mock 模式的接口证据不得缺失或降级。
  - body 要 JSON 格式化后用可折叠树展示：默认收起显示 `{…} N 个字段` / `[…] N 项`，点节点逐级展开，块右上角有「复制」（复制格式化后的完整 JSON）和「全部展开」。
  - 敏感头（`authorization` / `cookie` / `set-cookie` / `x-xsrf-token`）的值打码为 `***`。
  - 非文本响应（文件下载等）写成「文件名 / 大小 / 落盘路径」，不要硬塞二进制。
- **控制台报错**：`控制台` 块（原文 + 堆栈）+ `位置` 块。
- **断言不符**：`选择器`、`期望`、`实际`、`页面文案`、`位置`，缺的项不渲染；期望/实际里的英文状态值翻成中文（`visible` → 可见、`hidden` → 不可见、`element(s) not found` → 未找到该元素）。
- **脚本异常**：`错误`（原始消息前若干行）+ `位置`。

### 明确不要的东西

- 不要「关联问题」「规格依据」「复现路径」「失败原因分析」这类字段。
- 不要用中文重述断言（例如把 `toBe(1)` 翻译成「预期应发起一次请求」）——预期语义由**步骤句子**承载，报告只给原始证据。

## 四、机器可读报告（report-data.json）

```json
{
  "schemaVersion": 1,
  "schema": { "status": "…", "error.category": "…" },
  "generatedAt": "ISO 时间",
  "durationMs": 0,
  "mode": "mock | real",
  "runStatus": "passed | failed | …",
  "summary": { "total": 0, "passed": 0, "failed": 0, "skipped": 0 },
  "scenarios": [
    {
      "id": "s1",
      "caseId": "PRJ-001（用例编号，模块前缀-序号）",
      "title": "业务场景一句话（写预期结果，不写缺陷现状）",
      "domain": "业务域（不设「错误与边界」「联调环境验证」这类横切域）",
      "branch": "业务分支",
      "status": "passed | failed | skipped",
      "durationMs": 0,
      "file": "specs/xxx.spec.ts",
      "line": 0,
      "steps": [{ "index": 1, "text": "操作 + 应发生什么", "image": "assets/001-xxx/01.jpg" }],
      "failedStepIndex": 1,
      "mark": { "l": 10, "t": 20, "w": 30, "h": 5 },
      "error": {
        "category": "console | http | assert | script",
        "summary": "一行机械摘要",
        "blocks": [{ "label": "请求", "kind": "http", "text": "…" }],
        "raw": { "http": [], "console": [], "assertion": {}, "location": "" }
      }
    }
  ]
}
```

`error.raw` 是给 AI Agent 用的完整证据，页面只渲染 `blocks`。

`mode` 取本轮真实运行模式：`mock` 表示请求由项目 MSW handlers 应答，`real` 表示直连真实后端。两种模式的证据要求一致。

## 五、验收清单

- [ ] 状态只有三种，页面全文搜不到「已知问题 / 关联问题 / 规格依据 / 复现路径」。
- [ ] 列表页三层缩进正确，空分组不显示。
- [ ] 每个非跳过场景都有步骤和截图；截图不是灰屏、不是加载遮罩。
- [ ] 失败场景：出错步骤标红、证据分类正确、红框只出现一层。
- [ ] 接口证据的请求/响应是完整原文且已脱敏；JSON 树能展开、全部展开、复制。
- [ ] 断言证据含源码、期望、实际；元素不存在时给「未找到该元素」而不是空。
- [ ] `report-data.json` 有 `schemaVersion` 与 `schema`，失败场景带 `error.raw`。
- [ ] 报告目录已 gitignore，且 dev server 不监听它。
- [ ] 页面无前端报错（打开报告控制台干净）。
