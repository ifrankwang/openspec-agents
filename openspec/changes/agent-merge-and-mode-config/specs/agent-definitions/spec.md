## Purpose

定义物理 agent 合并后的定义内容组织：系统仅提供开发者与审查者两个物理 agent 定义、权限取各原身份并集，审查行为受"只报不改"指令约束（文档与注释类问题可直接修改），以及 simple 审查者承担确定性检查与任务验证的职责边界。

## ADDED Requirements

### Requirement: 仅两个物理 agent 定义

系统 SHALL 仅提供开发者与审查者两个物理 agent 定义；各逻辑身份 SHALL 不再拥有独立 agent 定义，任何逻辑身份的调用 SHALL 经由这两个物理 agent 之一承载。

#### Scenario: 逻辑身份经由物理 agent 承载
- **WHEN** 调用方请求任一逻辑身份的审查或开发能力
- **THEN** 该调用经由开发者或审查者物理 agent 承载，且不存在独立的逻辑身份定义

### Requirement: 物理权限取并集

合并后的物理 agent 权限 SHALL 取原各身份权限的并集；以维度审查者逻辑身份发起的调用 SHALL 具备编辑与写入能力。

#### Scenario: 维度审查者具备写权限
- **WHEN** 以维度审查者逻辑身份调用审查者 agent
- **THEN** 该调用具备编辑与写入能力

### Requirement: 审查者只报不改

审查者 SHALL 以只报不改为默认行为：对影响代码运行的逻辑类问题只上报、不修改；对文档、注释等不影响代码运行的问题 SHALL 可直接修改；该约束 SHALL 同时适用于 full 模式的维度审查。

#### Scenario: 逻辑类问题只报不改
- **WHEN** 审查者发现影响代码运行的逻辑类问题
- **THEN** 只上报 issue，不直接修改相关代码

#### Scenario: 文档注释类问题可直接修改
- **WHEN** 审查者发现文档或注释等不影响代码运行的问题
- **THEN** 可直接修改该类内容

#### Scenario: full 模式同样适用只报不改
- **WHEN** full 模式维度审查发现逻辑类问题
- **THEN** 同样只上报不修改

### Requirement: simple 审查者执行确定性检查与任务验证

simple 模式的审查者 SHALL 被允许运行确定性工具检查并承担任务验证职责；对工具的改进建议 SHALL 仅上报，由开发者实施。

#### Scenario: simple 审查者运行确定性检查
- **WHEN** simple 审查者在审查环节执行确定性工具检查
- **THEN** 检查被允许执行，其结果纳入质量审查结论

#### Scenario: 工具改进建议由开发者实施
- **WHEN** 审查者提出工具改进建议
- **THEN** 建议仅上报记录，实施工作由开发者完成
